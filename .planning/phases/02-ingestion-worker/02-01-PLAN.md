    Create Services/BallDontLieClient.cs in namespace NbaTracker.Worker.Services:

    The class takes `HttpClient http` in constructor (typed client pattern — IHttpClientFactory manages the instance).

    **GetGamesAsync(int season, DateOnly? date, CancellationToken ct) -> List&lt;BdlGame&gt;**
    - Cursor-based pagination loop: build URL with `seasons[]={season}&per_page=100`
    - If `date` is provided, add `&dates[]={date:yyyy-MM-dd}` to narrow to a single day
    - On each iteration: GET the URL, deserialize BdlPagedResponse&lt;BdlGame&gt;, append Data, check Meta.NextCursor
    - Continue while NextCursor has a value; pass `&cursor={nextCursor}` on the next request
    - Return accumulated list

    **GetTeamsAsync(CancellationToken ct) -> List&lt;BdlTeam&gt;**
    - Single paginated fetch of `/teams?per_page=100` — all 30 NBA teams fit in one page
    - Follow same cursor pattern in case pagination is needed
    - Return all teams

    **Register in Program.cs** (add before host.Build()):
    ```csharp
    builder.Services.AddHttpClient<BallDontLieClient>(client =>
    {
        client.BaseAddress = new Uri("https://api.balldontlie.io/nba/v1/");
        client.DefaultRequestHeaders.Add("Authorization", builder.Configuration["BallDontLie:ApiKey"]!);
    })
    .AddResilienceHandler("BdlRetry", pipeline =>
    {
        pipeline.AddRetry(new HttpRetryStrategyOptions
        {
            MaxRetryAttempts = 3,
            BackoffType = DelayBackoffType.Exponential,
            UseJitter = true,
            Delay = TimeSpan.FromSeconds(2)
        });
        pipeline.AddTimeout(TimeSpan.FromSeconds(30));
    });
    ```

    **Important implementation notes:**
    - Use `GetFromJsonAsync<BdlPagedResponse<BdlGame>>` from System.Net.Http.Json (included in .NET 9)
    - Do NOT add a rate-limit delay inside the client — the SyncOrchestrator controls pacing
    - The retry handler wraps the HttpClient, so transient failures are retried transparently before the caller sees an exception
    - If all 3 retries fail, the exception propagates to the caller (SyncOrchestrator catches it per the partial-run design)
    - Use `JsonSerializerOptions` with `PropertyNameCaseInsensitive = true` if needed for the deserialization call
