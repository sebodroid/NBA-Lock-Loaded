<task type="auto">
  <name>Task 2: Create nginx/nginx.prod.conf (API gateway only)</name>
  <files>nba-lines-tracker/nginx/nginx.prod.conf</files>
  <action>
Create the directory `nba-lines-tracker/nginx/` and write `nba-lines-tracker/nginx/nginx.prod.conf`. This is an API-gateway-only config — it has NO static file serving, NO SPA try_files fallback. The React SPA is on Cloudflare Pages.

Key rules for this config (per locked decisions):
- Listen on port 80 (Cloudflare terminates HTTPS; Nginx never sees TLS)
- NEVER add `return 301 https://` redirect — this causes an infinite redirect loop with Cloudflare Flexible SSL
- Use `$http_x_forwarded_proto` (not `$scheme`) for X-Forwarded-Proto header, because `$scheme` will always be `http` since Cloudflare connects to Nginx over HTTP

Config structure:
```nginx
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    server {
        listen 80;
        server_name _;

        location /api/ {
            proxy_pass         http://api:8080/api/;
            proxy_http_version 1.1;
            proxy_set_header   Host              $host;
            proxy_set_header   X-Real-IP         $remote_addr;
            proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
            proxy_set_header   X-Forwarded-Proto $http_x_forwarded_proto;

            # CORS: allow all origins (per user decision — small friend-group app)
            add_header         Access-Control-Allow-Origin  *;
            add_header         Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS";
            add_header         Access-Control-Allow-Headers "Authorization, Content-Type";

            if ($request_method = OPTIONS) {
                return 204;
            }
        }

        # Health check for monitoring
        location /health {
            return 200 "OK";
            add_header Content-Type text/plain;
        }

        # All other routes: 404 — SPA is on Cloudflare Pages, not here
        location / {
            return 404;
        }
    }
}
```

Note: The `proxy_pass http://api:8080/api/;` uses the Docker Compose service name `api` — containers in the same Compose network resolve each other by service name.
