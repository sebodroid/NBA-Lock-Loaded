**Two-job structure (per Claude's discretion and research recommendation):**
- Job 1: `build-and-push` — runs on ubuntu-latest, needs `permissions: packages: write` (without this, GITHUB_TOKEN cannot push to GHCR)
- Job 2: `deploy` — runs after job 1 via `needs: build-and-push`, uses appleboy/ssh-action to SSH to Droplet

**Image tagging strategy (Claude's discretion — SHA + latest):** Both `latest` and `sha-${{ github.sha }}` tags. Latest enables simple `docker compose pull` on the Droplet; SHA provides rollback traceability.

**Critical distinctions:**
- `GITHUB_TOKEN` is used ONLY in the build-and-push job for pushing to GHCR (it works in the Actions runner context)
- `GHCR_TOKEN` secret (a PAT with `read:packages`) is used in the SSH deploy script for `docker login` on the Droplet (GITHUB_TOKEN cannot authenticate outside the Actions runner)
- CI must NEVER write to `.env` on the Droplet — only `docker compose pull` and `docker compose up -d`

**Context path note:** The repo root is the Claude workspace (C:/Users/barne/Coding/Claude/), not nba-lines-tracker/. The Dockerfiles live at `nba-lines-tracker/src/NbaTracker.Api/Dockerfile`. Set `context: nba-lines-tracker` so the build context is the .NET solution directory.

Full workflow content to write (add the secrets comment block at the top):

```yaml
# Required GitHub Actions secrets (Settings -> Secrets and variables -> Actions):
# DROPLET_HOST    — Droplet IP address (e.g., 143.198.x.x)
# DROPLET_USER    — SSH login username (typically 'root')
# DROPLET_SSH_KEY — Full content of ed25519 private key (including -----BEGIN/END lines)
# GHCR_TOKEN      — GitHub PAT with read:packages scope (classic PAT, not fine-grained)

name: Build and Deploy

on:
  push:
    branches: [main]

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    steps:
      - uses: actions/checkout@v4

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push API image
        uses: docker/build-push-action@v6
        with:
          context: nba-lines-tracker
          file: nba-lines-tracker/src/NbaTracker.Api/Dockerfile
          push: true
          tags: |
            ghcr.io/${{ github.repository }}/api:latest
            ghcr.io/${{ github.repository }}/api:sha-${{ github.sha }}

      - name: Build and push Worker image
        uses: docker/build-push-action@v6
        with:
          context: nba-lines-tracker
          file: nba-lines-tracker/src/NbaTracker.Worker/Dockerfile
          push: true
          tags: |
            ghcr.io/${{ github.repository }}/worker:latest
            ghcr.io/${{ github.repository }}/worker:sha-${{ github.sha }}

  deploy:
    needs: build-and-push
    runs-on: ubuntu-latest

    steps:
      - name: Deploy to Droplet via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.DROPLET_HOST }}
          username: ${{ secrets.DROPLET_USER }}
          key: ${{ secrets.DROPLET_SSH_KEY }}
          port: 22
          script: |
            echo "${{ secrets.GHCR_TOKEN }}" | docker login ghcr.io -u ${{ github.actor }} --password-stdin
            cd /home/deploy/app
            git pull origin main
            cd nba-lines-tracker
            docker compose -f docker-compose.prod.yml pull
            docker compose -f docker-compose.prod.yml up -d --remove-orphans
            docker image prune -f
```

Notes:
- `git pull origin main` before `docker compose pull` keeps docker-compose.prod.yml in sync on the Droplet (avoids the SCP anti-pattern of potentially overwriting .env).
- `--remove-orphans` ensures any container removed from the Compose definition is stopped on the Droplet.
- `docker image prune -f` cleans up old image layers to prevent Droplet disk filling up.
