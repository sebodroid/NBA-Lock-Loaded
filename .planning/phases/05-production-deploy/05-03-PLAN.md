<task type="checkpoint:human-action">
  <name>Task 1: Prepare the DigitalOcean Droplet and configure GitHub Actions secrets</name>
  <action>
HUMAN ACTION REQUIRED. Claude cannot SSH to the Droplet or configure GitHub secrets.

The Droplet needs Docker, the app directory, .env, nginx config, and an SSH key. GitHub Actions needs four secrets to deploy.

Step 1: Generate an SSH key pair for CI/CD (run on your local machine)
  ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/do_deploy_key -N ""

Step 2: Add the public key to the Droplet
  ssh-copy-id -i ~/.ssh/do_deploy_key.pub root@DROPLET_IP
  (or add it in the DigitalOcean dashboard when creating the Droplet)

Step 3: SSH into the Droplet and run setup commands
  ssh -i ~/.ssh/do_deploy_key root@DROPLET_IP

  On the Droplet:
    curl -fsSL https://get.docker.com | sh
    git clone https://github.com/OWNER/REPO.git /home/deploy/app
    cp /home/deploy/app/nba-lines-tracker/.env.example /home/deploy/app/nba-lines-tracker/.env
    nano /home/deploy/app/nba-lines-tracker/.env
    -- fill in ConnectionStrings__Default with Aiven host + SslMode=Require
    -- fill in JWT__Secret (generate: openssl rand -base64 32)
    -- fill in BDLAPI__Key, OddsAPI__Key, Seed__AdminEmail, Seed__AdminPassword
    docker compose version  (verify Docker plugin works)

Step 4: Create a GitHub PAT for GHCR pulls
  GitHub.com -> Settings -> Developer settings -> Personal access tokens -> Tokens (classic)
  Generate new token -> scope: read:packages -> copy the token value

Step 5: Add four GitHub Actions secrets to the repo
  Repo -> Settings -> Secrets and variables -> Actions -> New repository secret:
    DROPLET_HOST    = Droplet IP address (e.g., 143.198.x.x)
    DROPLET_USER    = SSH username (typically root)
    DROPLET_SSH_KEY = Full content of ~/.ssh/do_deploy_key including BEGIN/END lines
                      (print with: cat ~/.ssh/do_deploy_key)
    GHCR_TOKEN      = The GitHub PAT from step 4 (read:packages scope)
  </action>
  <verify>
On the Droplet:
  docker compose version (exits 0, shows v2.x)
  ls /home/deploy/app/nba-lines-tracker/docker-compose.prod.yml (file exists from git clone)
  ls /home/deploy/app/nba-lines-tracker/.env (file exists, NOT tracked by git)
  grep SslMode /home/deploy/app/nba-lines-tracker/.env (shows SslMode=Require with real Aiven host, not REPLACE_ME)

In GitHub repo Settings -> Secrets and variables -> Actions: all four secrets appear.
  </verify>

<task type="checkpoint:human-action">
  <name>Task 2: Trigger first deployment and set up Cloudflare Pages + Access</name>
  <action>
HUMAN ACTION REQUIRED. Claude cannot trigger GitHub Actions or configure the Cloudflare dashboard.

Step 1: Trigger the first deployment
  git commit --allow-empty -m "chore: trigger initial production deployment"
  git push origin main

  Watch github.com/OWNER/REPO/actions:
    build-and-push job: ~3-5 minutes (builds .NET + pushes two Docker images to GHCR)
    deploy job: ~30 seconds after (SSH pull + restart)

  If deploy job fails, check logs on Droplet:
    ssh -i ~/.ssh/do_deploy_key root@DROPLET_IP
    cd /home/deploy/app/nba-lines-tracker
    docker compose -f docker-compose.prod.yml logs --tail=50

Step 2: Verify the API is reachable
  curl http://DROPLET_IP/api/health  -> Expected: 200 OK
  curl http://DROPLET_IP/api/teams   -> Expected: 401 Unauthorized
  curl http://DROPLET_IP/            -> Expected: 404 Not Found

Step 3: Set up Cloudflare Pages for the React SPA
  Cloudflare dashboard -> Workers and Pages -> Create application -> Pages
  Connect to Git -> select the repo
  Build settings:
    Production branch: main
    Build command: npm run build
    Build output directory: dist
    Root directory (advanced): nba-lines-tracker/frontend
  Environment variable (Production):
    VITE_API_URL = http://DROPLET_IP/api
  Click Save and Deploy -> note the *.pages.dev URL assigned

Step 4: Configure Cloudflare Access (email OTP gate)
  Simpler path via Pages dashboard:
    Workers and Pages -> select Pages project -> Manage -> Access policy -> Enable Cloudflare Access
    Click Manage Policies -> add approved email addresses -> set login method = One-time PIN

  Alternative via Zero Trust dashboard:
    Zero Trust -> Settings -> Authentication -> Add One-Time PIN identity provider
    Zero Trust -> Access -> Applications -> Add -> Self-hosted
    Domain: <project>.pages.dev
    Policy: Action = Allow, Emails = approved addresses, Login = One-time PIN

Step 5: Test end-to-end in an incognito browser
  Navigate to https://<project>.pages.dev
  Expected: Cloudflare Access OTP challenge (not the app directly)
  Enter approved email -> receive OTP code -> enter it
  Expected: NBA Lines Tracker login page appears
  Log in with Seed__AdminEmail / Seed__AdminPassword
  Expected: Team grid loads with real NBA data
